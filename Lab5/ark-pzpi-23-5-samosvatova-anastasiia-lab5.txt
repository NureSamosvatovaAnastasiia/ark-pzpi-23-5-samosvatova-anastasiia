2 ОПИС ВИКОНАНОЇ РОБОТИ

     Для виконання лабораторної роботи було здійснено розгортання програмної системи моніторингу теплиць AgroSense з використанням технології контейнеризації Docker. Це дозволило автоматизувати процес запуску всіх компонентів системи (бази даних, серверної частини, MQTT-брокера та IoT-пристроїв) в ізольованому середовищі.
   Архітектура розгортання розділена на дві логічні частини (Server та IoT) і включає наступні сервіси:
• контейнер бази даних (agro_db): Розгорнуто на базі образу postgres:15-alpine. Використовується для надійного зберігання облікових даних користувачів, ідентифікаторів теплиць (GREENHOUSE_ID) та історичних даних показників;
• контейнер міграцій (db_migrate): Тимчасовий сервіс, який виконує команду npm run db:push для автоматичного створення актуальної структури таблиць у базі даних при запуску;
• контейнер сервера (agro_api): Забезпечує REST API на порту 3000, виконує JWT-автентифікацію та обробку запитів від клієнтських застосунків та IoT-мосту;
• контейнер брокера повідомлень (mqtt_broker): Використовує образ somevt/agrosense-mqtt (Mosquitto) для забезпечення обміну повідомленнями між пристроями за протоколом MQTT (порти 1883, 9001);
• контейнер IoT-мосту (iot_bridge): Слугує посередником, який підписується на MQTT-топіки та пересилає отримані дані на HTTP API сервера, використовуючи внутрішню адресацію host.docker.internal;
• контейнер емулятора пристрою (iot_device): Емулює роботу реального контролера теплиці, генерує показники сенсорів та надсилає їх до MQTT-брокера.
   Весь програмний код наведено у Додатку Б.
   Ключові інженерні рішення при розгортанні:
• Модульність конфігурації: Використано два окремих маніфести (docker-compose.server.yml та docker-compose.iot.yml), що дозволяє розгортати серверну частину та IoT-клієнтів незалежно один від одного;
• Інтерактивна автоматизація: Розроблено Bash-скрипти (agro_api_start.sh та agro_iot_start.sh), які запитують у користувача конфігураційні дані (Email, пароль, ID теплиці, JWT-ключ) та експортують їх як змінні оточення перед запуску контейнерів;
• Механізм Healthcheck: Налаштовано перевірку стану бази даних (pg_isready), що гарантує запуск API та міграцій лише після повної готовності PostgreSQL;
• Мережева взаємодія: Для зв’язку IoT-контейнерів із локальним API сервером використано налаштування extra_hosts, що забезпечує коректну маршрутизацію запитів з контейнера iot_bridge на хост-машину.
   Було перевірено взаємодію компонентів: емулятор пристрою успішно підключається до брокера, міст транслює дані на сервер, а інформація зберігається в базі даних agro_db. 



















4 ВИСНОВКИ
     
     У ході виконання лабораторної роботи було успішно виконано розгортання програмної системи “AgroSense” за допомогою Docker та Docker Compose. Застосування контенеризації дозволило вирішити проблему сумісності оточень та забезпечити швидкий старт системи на будь-якому комп’ютері. Перевірка роботи системи підтвердила повну працездатність бізнес-логіки: від збору даних віртуальними сенсорами до їхнього статистичного аналізу на сервері та збереження у базі даних PostgreSQL.
